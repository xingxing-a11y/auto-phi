# ▶ 位置校准：点不中「开始演奏」时怎么办

> 适用：换了一台新手机后，点「开始演奏」却一直没反应（界面显示在跑、约 20 秒后超时、屏幕上一次触摸都没有）。
>
> 本文只讲位置。时间偏（Good 太多 / 偏早偏晚）请看 `c` 与 `K` 的说明，两者不要混。
>
> 两个入口：顶部那行 `▶ 落点 x,y`（点它开弹窗），以及同一行右侧的 `测试 ▶`。

## 0. 先分清两件事

| 症状 | 是位置问题吗 | 去哪看 |
|---|---|---|
| 点了「开始演奏」，屏幕全程没有任何触摸，约 20 秒后超时 | 是，很可能是 | 本文 |
| 打起来了，但 Good 很多 / 偏早偏晚 | 不是，是时间问题 | 调 `c` / `K` |
| 点了没反应，日志里有「没有 Shizuku 注入代理」 | 不是，是 Shizuku 没授权 | 先给 Shizuku 权限 |

## 1. ▶ 的位置是从哪来的

有两个来源，按优先级取：

| 优先级 | 来源 | 什么时候用 |
|---|---|---|
| 1 | 学到的坐标（你在游戏里亲手点过一次） | 学过、且设备指纹没变 |
| 2 | 出厂比例 | 从没学过，或学到的已失效 |

出厂比例是：

```
x = 屏幕横屏宽 × 0.9458
y = 屏幕横屏高 × 0.8549
```

这个比例是在一台 1610×720 的机器上实测标定的，在那台机器上落在 ▶ 正中心。
但 Phigros 的按钮是斜切形状，不同机型 / 不同宽高比下 UI 会重排，所以比例会偏 ——
偏了就点空。而注入器不校验点到了什么，日志照样写「已点 ▶」，游戏却没开始。

这也是为什么现在改成「你自己点一次，App 记住那一下」。

## 2. 怎么自测（不用打歌）

1. 打开 Phigros，停在选曲页（能看到右下角 ▶ 的那一页）；
2. 回到本 App，点顶部那行右侧的 `测试 ▶`；
3. 马上切回游戏（按最近任务键 / 边缘返回），停在选曲页；
4. 4 秒后 App 会自动发一次点击，看画面：

| 看到什么 | 结论 |
|---|---|
| 游戏开始加载 / 进入游玩 | 位置正确，不用调 |
| 画面完全没变 | 点空了，去第 3 节重新学一次 |
| 点到了别的东西（难度变了、曲目变了） | 偏得比较多，同样去第 3 节，但学的时候要更准 |

为什么必须等这 4 秒：你按下按钮的那一刻，前台是本 App 自己。
如果立刻就点，这一下会落在 App 的界面上（正好在右下角），游戏那边什么都没发生 ——
你会得到一个假的「点不中」结论。这 4 秒就是留给你切回游戏的时间。

`测试 ▶` 只发一次点击，不注入任何音符，也不影响之后正常打歌。
4 秒内没切回去也没关系：那一下会点在 App 上，重来一次即可，不会误触游戏的其它按钮。

想亲眼看到落点在哪（最直观的一招）：系统设置 →「开发者选项」→ 打开「显示触摸操作」，
再点一次 `测试 ▶`。屏幕上会留下白点 / 圆圈，那就是我们的落点 —— 拿它和右下角 ▶ 比，
就知道学的时候该点哪里。这一步不用改任何设置，也不用打歌。

## 3. 点不中怎么办：重新学一次

弹窗里只有这一个可动的东西 —— `▸ 学习落点`。流程是：

1. 切回游戏，停在选曲页（先别点任何东西）；
2. 回 App，点顶部 `▶ 落点 …` 那行字打开弹窗，点 `▸ 学习落点`；
3. 屏幕提示「4 秒后开始监听：请切回游戏停在选曲页」—— 立刻切回游戏，停在选曲页；
4. 等提示变成 「现在开始监听 15 秒：点一下「开始演奏」」，这时候在游戏里点一次右下角的「开始演奏」；
5. 回到 App，看那行字的「来源」：变成 `已学到 …` 就成功了，同时会有一条 toast 写着 `已记录 x,y`。

四条必须遵守的：

- 只记录第一次点击。 先点了难度 / 曲目 / 返回键，那个位置就会被当成按钮，之后打歌会点空；
- 必须在提示「现在开始监听」之后点。 前 4 秒是留给你切 App 的，那段时间还没开始听；
- 学歪了再点一次 `▸ 学习落点` 重学，不用先清空；
- 学到的点存的是比例，所以同一个宽高比下换分辨率也大致可用；但宽高比一变，它会自动失效（见第 6 节）。

## 4. 怎么确认学对了

看那行字的「来源」，只有三种：

| 显示 | 含义 |
|---|---|
| `默认 0,0` | 从没学过，正在用出厂比例 |
| `已学到 2026-11-01 14:32` | 用的是你学到的点 |
| `学到的已失效（1610x720 学于 …）` | 换过设备或分辨率，已回落出厂比例，需要重学 |

再点一次 `测试 ▶` 做最终确认 —— 游戏开始加载 = 位置对。

日志可以从两个地方看：

| 地方 | 看到什么 | 注意 |
|---|---|---|
| App 界面日志 | 点「日志 ▸ 展开」后是本轮全部行（固定高度、内部滑动） | 收起时整块不显示，只留一行标题 |
| `logcat` | 完整一份（和界面同一来源） | 会被游戏日志冲掉，出问题尽快抓 |

注意区分：界面能看到全部，但 App 内部只留最近 600 行（环形缓冲，一轮约 40 行，碰不到）。
真要长期留证据还是用 `logcat`。

抓法（Git Bash，全路径不用改 PATH）：

```bash
D:/platform-tools/adb.exe logcat -s PgPlay
```

`测试 ▶` 会打出这两行：

```
测试点击已发出（按下后 4.0 s）：1553.0,619.0（来源 已学到 …；屏幕 1610x720） ⇒ 游戏开始加载=位置对；没反应=用「▶ 落点」→「学习落点」重记一次
▶ 落点 ✓ 在框内（距中心 左15 下4 px；余量 左58 右87 上58 下50）⇒ 落在框内≠点得中；用「▶ 落点」→「学习落点」重记一次（手填偏移已于 10-31 取消）
```

第二行是三档判读（`✓ 在框内` / `⚠ 贴边` / `✗ 出界`）。它只出现在日志里，
弹窗里不显示 —— 因为那个框是在一台机器上量出来的，中心偏了 13 px，
而且源码里刻意不写「对准」（写了会让人以为位置已被验证）。最终判据永远是第 2 节的 `测试 ▶`。

真打歌起手会多打一行 `▶ 位置 …（来源 … × 1610x720）`，点完再一行 `点击 ▶ 成功：注入完成 (x,y)`。

## 5. `恢复默认（0,0）` 到底是什么

这个按钮的名字容易误解。它不是把坐标设成 (0,0)（那样会点到屏幕左上角），而是：

把「学到的点」删掉，落点回到出厂比例。

所以：

- 学歪了点它 → 回到出厂比例，再按第 2 节测一次；
- 想让落点更准 → 别点它，直接重学一次就行（重学会覆盖旧值）；
- 换设备后不需要点它 —— 指纹一变，学到的点会自动失效。

## 6. 换设备 / 换分辨率

学到的点带着设备指纹：厂商 + 型号 + 设备代号 + 屏幕宽高。

- 换手机 → 指纹变了 → 自动失效，落回出厂比例，重新学一次；
- 只改分辨率 / 改显示大小 → 宽高进了指纹，同样自动失效；
- 所以不用担心「旧坐标带到新机器上」：它不会硬用。

判断当前用的是哪一档，看那行字的「来源」（第 4 节那张表）。

## 7. 和 `c` / `K` 的区别（别搞混）

| 量 | 管什么 | 单位 | 在哪 |
|---|---|---|---|
| 本文 `▶ 落点` | ▶ 按钮在哪 | 屏幕坐标 | 顶部 `▶ 落点 …` |
| `c` | 设备时间滞后（捕获链） | 毫秒 | 顶部 `c=… ms` |
| `K` | 曲目起音形状偏置 | 毫秒 | 顶部 `K=…`（每首一个） |

简单记：位置不对找 `▶ 落点`，成绩不对找 `c` / `K`。

## 8. 还是点不中怎么办

按这个顺序排除：

1. Shizuku 是否在运行（App 里显示「已授予 ✓」）—— 没它 App 没有「手」；
2. 是不是停在选曲页，且 4 秒内真的切回了游戏 —— 前台是 App 的话，点击落在 App 上；
3. 来源是不是 `默认 0,0` —— 说明从没学过，或学了没保存成功；重学一次；
4. 是否开了游戏助手 / 游戏空间 —— 会让判定与音频解耦，症状不同但看起来也像「打不了」；
5. 日志里的 `rawLines` —— 学习时若提示「15 秒内没等到点击，未记录（收到 N 行触摸输出：…）」：
   `N=0` 说明 `getevent` 没起来，`N>0` 但没解析出事件说明设备选错了，两种修法不同。
